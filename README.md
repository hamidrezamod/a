# پورتفولیوی حمیدرضا محمدی

### 🌐 آدرس سایت: **https://hamidrezamod.github.io/portfolio/**

سایت شخصی — تئاتر، نوشتن، فیلم کوتاه، پادکست، رزومه، افتخارات و اطلاعات تماس.

این پروژه با **React + Vite** ساخته شده و خروجی آن یک **سایت کاملاً ایستا (Static)** است که روی **GitHub Pages** منتشر می‌شود.
هیچ سرور، دیتابیس یا سرویس پولی لازم نیست.

افزونه روی GitHub Pages فعال است: **هر بار که فایلی را در شاخه `main` تغییر بدهی، سایت خودکار دوباره ساخته و منتشر می‌شود** (حدود ۱ تا ۲ دقیقه).

> **وضعیت فعلی (مرحله ۱):** نسخه دسکتاپ صفحه اصلی، مطابق اسکرین‌شات دیزاین و رفرنس تایپوگرافی، ساخته شده و **روی اینترنت منتشر شده است**.
> نسخه موبایل، صفحه کامل مقاله‌ها، صفحه کامل تئاتر، ترنزیشن‌های اختصاصی و پری‌لودر
> در مرحله‌های بعد و بر اساس دیزاین‌های ارسالی اضافه می‌شوند (معماری از قبل آماده است).

> **منو:** منوی سایت یک نوار شناور (Dock) در **پایین و وسط صفحه** است که با اسکرول همان‌جا می‌ماند،
> عرضش ثابت (**۴۴۳ پیکسل**) است، سطحی کمی تیره‌تر از رنگ اصلی سایت دارد و پشتش سایه افتاده است.
> آیتم **Works** باز و بسته می‌شود و زیرمجموعه‌هایش (Writings، Short Film، Theatre، Podcast)
> در پنلی بالای نوار ظاهر می‌شوند. فهرست آیتم‌ها فقط در یک فایل است: `src/content/site/navigation.js`.

## ۱) اجرای سایت روی کامپیوتر خودت

۱. برنامه **Node.js** را نصب کن (نسخه ۲۰ یا بالاتر): https://nodejs.org
۲. پوشه پروژه را در ترمینال باز کن و این دو فرمان را بزن:

```bash
npm install     # فقط بار اول؛ وابستگی‌ها را نصب می‌کند
npm run dev     # سرور محلی را اجرا می‌کند
```

۳. آدرسی که نمایش داده می‌شود (مثلاً `http://localhost:5173`) را در مرورگر باز کن.

### ساخت نسخه نهایی و پیش‌نمایش آن

```bash
npm run build     # فایل‌های نهایی در پوشه dist ساخته می‌شوند
npm run preview   # همان نسخه نهایی را نمایش می‌دهد
```

## ۲) ساختار پروژه (کدام پوشه برای چیست؟)

```text
portfolio/
├─ index.html                 صفحه اصلی سایت (HTML خام؛ معمولاً دست نمی‌زنی)
├─ package.json               فهرست ابزارها و فرمان‌ها
├─ vite.config.js             تنظیمات ساخت (نام مخزن برای GitHub Pages اینجاست)
├─ .github/workflows/deploy.yml   ساخت و انتشار خودکار روی GitHub Pages
├─ public/                    فایل‌های ثابت مثل favicon
└─ src/
   ├─ main.jsx                نقطه شروع برنامه
   ├─ App.jsx                 ریشه؛ صفحه اصلی + لایه پاپ‌آپ
   ├─ components/             قطعه‌های رابط کاربری
   │  ├─ layout/              منوی شناور پایین صفحه، فوتر، پوسته صفحه
   │  ├─ sections/            بخش‌های صفحه اصلی (هیرو، درباره من، نوشته‌ها، ...)
   │  ├─ cards/               کارت‌ها (نوشته، تئاتر، گواهی)
   │  ├─ media/               قاب تصویر و پلیر ویمیو
   │  ├─ ui/                  آیکون، عنوان بخش، فلش‌ها
   │  └─ overlay/             سیستم پاپ‌آپ جزئیات (مقاله / پروژه تئاتر)
   ├─ content/                ⭐ تمام متن‌ها و محتوای سایت (بدون هیچ کد طراحی)
   │  ├─ site/                نام، منو، اطلاعات تماس
   │  ├─ home/                متن بخش‌های صفحه اصلی
   │  ├─ writings/            مقاله‌ها (هر مقاله یک فایل .md)
   │  ├─ theatre/             پروژه‌های تئاتر (هر پروژه یک فایل .md)
   │  ├─ podcast/             پادکست
   │  ├─ resume/              رزومه
   │  └─ awards/              افتخارات و گواهی‌نامه‌ها
   ├─ assets/
   │  ├─ images/              تمام تصاویر WebP (فقط فایل را اینجا کپی کن)
   │  ├─ icons/               تمام آیکون‌های SVG
   │  └─ fonts/               فونت Crimson Pro (به‌صورت محلی، بدون اینترنت)
   ├─ styles/                 تمام ظاهر سایت
   │  ├─ tokens.css           ⭐ رنگ‌ها، فونت‌ها، اندازه‌ها، فاصله‌ها، زمان‌بندی حرکت
   │  ├─ typography.css       فونت‌ها و قواعد متن
   │  ├─ base.css             تنظیمات پایه
   │  ├─ layout.css           قاب صفحه و ریتم بخش‌ها
   │  └─ components/          استایل هر بخش به‌صورت جداگانه
   ├─ hooks/                  رفتارهای تعاملی (قفل اسکرول، کلید Escape، فوکوس)
   ├─ animation/              ⭐ جای ترنزیشن‌های آینده و پری‌لودر
   └─ utils/                  ابزارهای کوچک (خواندن متن، تبدیل Markdown، اسکرول)
```

**قاعده اصلی:** متن و محتوا فقط در `src/content` و `src/assets` زندگی می‌کند؛ ظاهر فقط در `src/styles`.
برای اینکه بفهمی چطور مقاله یا پروژه جدید اضافه کنی، راهنمای کامل را بخوان:

👉 [`docs/content-guide.md`](docs/content-guide.md)

## ۳) چیزهایی که فعلاً «جای خالی» هستند و بعداً می‌آیند

| مورد | وضعیت فعلی | برای کامل شدن چه لازم است |
| --- | --- | --- |
| **آیکون‌های SVG اصلی** | برای هر آیکون یک نمونه ساده و تمیز ساخته شده تا سایت ناقص به‌نظر نرسد | فایل SVG را با همان نام در `src/assets/icons/` بگذار (فهرست نام‌ها: `src/assets/icons/README.md`) |
| **فونت فارسی مقاله‌ها** | متن فارسی با فونت جانشین (Tahoma) نمایش داده می‌شود؛ هیچ خطایی هم رخ نمی‌دهد | فایل فونت را در `src/assets/fonts/persian/` بگذار (راهنما: همان پوشه) — خودکار فعال می‌شود |
| **آدرس گوگل‌درایو فیلم کوتاه** | آیکون گوگل‌درایو پنهان است تا لینک بی‌مقصد ساخته نشود | آدرس را در `src/content/home/short-film.js` بگذار — آیکون خودکار ظاهر می‌شود |
| **لینک‌های پادکست (Castbox و اینستاگرام پادکست)** | به‌صورت متن نمایش داده می‌شوند (نه لینک)، تا کاربر روی لینک خالی کلیک نکند | آدرس‌ها را در `src/content/home/podcast.js` بگذار — خودکار قابل کلیک می‌شوند |

هیچ‌کدام از این‌ها «کار نیمه‌تمام» به‌حساب نمی‌آیند: هر جای خالی، جای مشخصی دارد و با
گذاشتن یک فایل یا یک آدرس، بدون دست زدن به کد فعال می‌شود.

## ۴) انتشار روی GitHub Pages (گام‌به‌گام)

### الف) یک‌بار برای همیشه

۱. وارد https://github.com شو و روی **New repository** بزن.
۲. نام مخزن را دقیقاً `portfolio` بگذار (اگر اسم دیگری گذاشتی، در فایل `vite.config.js` مقدار `REPOSITORY_NAME` را به همان نام تغییر بده).
۳. مخزن را Public بگذار و بساز.
۴. فایل‌های پروژه را در مخزن قرار بده (راهنمای دقیق: [`docs/deploy-guide.md`](docs/deploy-guide.md)).
۵. در صفحه مخزن برو به: **Settings → Pages**
۶. در بخش **Build and deployment**، قسمت **Source** را از «Deploy from a branch» به **GitHub Actions** تغییر بده. (مهم!)
۷. برو به تب **Actions** و اگر لازم بود روی **Deploy to GitHub Pages** بزن و **Run workflow** را اجرا کن.
۸. چند دقیقه بعد، آدرس سایت این می‌شود:
   `https://نام‌کاربری‌گیت‌هاب.github.io/portfolio/`

از این به بعد **هر بار که فایل‌ها را در شاخه `main` تغییر بدهی، خودِ گیت‌هاب سایت را دوباره می‌سازد و منتشر می‌کند.**

### ب) بعد از هر تغییر (کاری که همیشه انجام می‌دهی)

> سایت شما الان همین‌جا زنده است: **https://hamidrezamod.github.io/portfolio/**
> و انتشار آن کاملاً خودکار است؛ نیازی به هیچ کار اضافه‌ای نیست.

اگر روی کامپیوتر خودت کار می‌کنی:

```bash
git add .
git commit -m "توضیح تغییر"
git push
```

اگر از سایت گیت‌هاب ویرایش می‌کنی: فایل را باز کن، متن را عوض کن، پایین صفحه **Commit changes** را بزن.

حدود ۱ تا ۲ دقیقه بعد، سایت خودکار به‌روز می‌شود. (تب Actions را نگاه کن؛ اگر تیک سبز گرفت یعنی همه‌چیز درست است.)

## ۵) نکته‌های فنی مهم

- **فونت:** Crimson Pro به‌صورت محلی در پروژه ذخیره شده است؛ سایت به گوگل فونت وابسته نیست و آفلاین هم درست نمایش داده می‌شود.
- **تایپوگرافی:** دقیقاً طبق رفرنس ارسالی — Hero ۱۲۸/۱۰۰/۶۰۰، Hero Subtitle ۳۴/۳۸/۴۰۰، Section Title ۶۴/۶۹/۶۰۰، Card Title ۴۰/۴۴/۶۰۰، Card Subtitle ۲۴/۳۰/۴۰۰، Card Body ۲۰/۳۱/۴۰۰، Menu و Button ۱۹px وزن ۵۰۰، Label ۱۶px وزن ۵۰۰. جدول کامل در `docs/content-guide.md`.
- **فیلم کوتاه:** پلیر ویمیو داخل سایت قابل پخش است (با کلیک روی دکمه پخش بارگذاری می‌شود) و زیر آن دو آیکون قابل کلیک ویمیو و گوگل‌درایو قرار دارد. آدرس گوگل‌درایو فعلاً خالی است؛ به‌محض وارد کردن آدرس در `src/content/home/short-film.js` آیکون آن هم نمایش داده می‌شود.
- **تصاویر:** همه WebP هستند و پایین صفحه به‌صورت lazy بارگذاری می‌شوند؛ اندازه تصویرها از قبل به مرورگر اعلام می‌شود تا چیدمان نپرد.
- **ویدیو:** ویمیو فقط پس از کلیک کاربر بارگذاری می‌شود و تصویر جانشین همیشه سرجایش می‌ماند؛ پس پلیر خراب هیچ‌وقت چیدمان را به‌هم نمی‌ریزد.
- **مقاله‌ها و پروژه‌های تئاتر** به‌صورت پاپ‌آپ تمام‌صفحه باز می‌شوند (بدون بارگذاری صفحه جدید). با کلید `Esc` یا دکمه Close یا دکمه Back مرورگر بسته می‌شوند.
- **دسترس‌پذیری:** ساختار معنایی HTML، امکان حرکت با کیبورد، مدیریت فوکوس در پاپ‌آپ و احترام به تنظیم «کاهش حرکت» سیستم.
