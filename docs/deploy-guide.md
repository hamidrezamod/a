# راهنمای انتشار روی GitHub Pages

این راهنما برای کسی نوشته شده که طراح است و برنامه‌نویس حرفه‌ای نیست. سه روش داریم؛
**روش دوم (GitHub Desktop) ساده‌ترین و مطمئن‌ترین است.**

---

## مهم‌ترین نکته

سایت با **GitHub Actions** ساخته و منتشر می‌شود؛ یعنی تو فقط **فایل‌های متن و تصویر پروژه** را در مخزن می‌گذاری
و گیت‌هاب خودش سایت را می‌سازد. پس:

- فایل‌های زیر را **هرگز** آپلود نکن: `node_modules` و `dist` (فقط حجم مخزن را زیاد می‌کنند).
- فایل `package-lock.json` را حتماً آپلود کن (گیت‌هاب با آن نسخه ابزارها را دقیق نصب می‌کند).

---

## روش ۱: ساخت مخزن (یک‌بار برای همیشه)

۱. وارد https://github.com شو (اگر حساب نداری، بساز).
۲. بالا-راست روی **+** و بعد **New repository** بزن.
۳. `Repository name` را بگذار: `portfolio`
۴. گزینه **Public** را انتخاب کن.
۵. تیک `Add a README file` را **نزن** (چون README خودمان را داریم).
۶. روی **Create repository** بزن.

---

## روش ۲ (پیشنهادی): آپلود با GitHub Desktop

۱. برنامه **GitHub Desktop** را نصب کن: https://desktop.github.com
۲. با حساب گیت‌هابت وارد شو.
۳. منوی **File → Clone repository → GitHub.com** و مخزن `portfolio` را انتخاب کن و Clone بزن.
۴. پوشه‌ای که Clone شد را در فایل‌کاوشگر (Finder/Explorer) باز کن.
۵. **تمام فایل‌ها و پوشه‌های پروژه** را داخل آن پوشه کپی کن (فقط `node_modules` و `dist` را کپی نکن).
۶. در GitHub Desktop پایین-چپ یک توضیح کوتاه بنویس، مثلاً: `Initial portfolio`
۷. روی **Commit to main** بزن، بعد روی **Push origin**.
۸. تمام. برو به مرحله «فعال‌سازی GitHub Pages».

---

## روش ۳: آپلود از خود سایت گیت‌هاب (بدون نصب برنامه)

در صفحه مخزن: **Add file → Upload files** و فایل‌ها را با موس بکش و رها کن.
(برای پوشه‌های تودرتو راحت‌تر است همه را در یک فایل ZIP آماده کنی، ولی گیت‌هاب فایل‌های داخل ZIP را خودکار باز نمی‌کند؛
پس اگر تعداد فایل‌ها زیاد است، همان روش GitHub Desktop را انتخاب کن.)

---

## روش ۴: با ترمینال (اگر Git نصب داری)

```bash
git clone https://github.com/USERNAME/portfolio.git
cd portfolio
# فایل‌های پروژه را داخل این پوشه کپی کن
git add .
git commit -m "Initial portfolio"
git push
```

---

## فعال‌سازی GitHub Pages (خودکار شدن انتشار)

۱. در صفحه مخزن برو به **Settings**.
۲. در ستون چپ روی **Pages** بزن.
۳. در بخش **Build and deployment**:
   - **Source** را از `Deploy from a branch` به **GitHub Actions** تغییر بده.
   - (اگر گزینه Branch را دیدی، هیچ شاخه‌ای انتخاب نکن؛ فقط Source را روی GitHub Actions بگذار.)
۴. برو به تب **Actions**.
۵. اگر ساخت خودکار شروع نشده بود، روی **Deploy to GitHub Pages** کلیک کن و **Run workflow** بزن.
۶. منتظر بمان تا دو مرحله (build و deploy) تیک سبز بگیرند (۱ تا ۳ دقیقه).
۷. آدرس سایت در همان صفحه Actions (بخش deploy) نوشته می‌شود؛ معمولاً:
   `https://USERNAME.github.io/portfolio/`

---

## اگر نام مخزن را چیز دیگری گذاشتی

فایل `vite.config.js` را باز کن و این خط را پیدا کن:

```js
const REPOSITORY_NAME = 'portfolio';
```

نام مخزن خودت را جای `portfolio` بگذار، ذخیره کن، و دوباره Push کن.

اگر بعداً **دامنه اختصاصی** (مثلاً `hamidrezamohammadi.com`) وصل کردی:

```js
const REPOSITORY_NAME = '';   // و در این حالت base برابر '/' خواهد بود
```

(در این صورت لازم است در تنظیمات Pages بخش Custom domain هم دامنه را وارد کنی.)

---

## بعد از هر به‌روزرسانی چه کنم؟

۱. فایل‌های تغییر‌یافته را در پوشه پروژه ذخیره کن.
۲. با GitHub Desktop: توضیح بنویس → **Commit to main** → **Push origin**.
   (یا در ترمینال: `git add . && git commit -m "توضیح" && git push`)
۳. تب **Actions** را نگاه کن؛ یک ساخت جدید شروع می‌شود.
۴. وقتی تیک سبز دیدی، سایت به‌روز شده است.
۵. اگر می‌خواهی اول روی کامپیوتر خودت ببینی: `npm run dev`

---

## اگر ساخت (build) خطا داد چه کنم؟

- تب **Actions** → روی ساخت قرمز کلیک کن → مرحله قرمز را باز کن و متن خطا را بخوان.
- شایع‌ترین علت خطا، اشتباه تایپی در فایل‌های `src/content` است. اشتباه را برگردان (Undo)، Push کن و دوباره امتحان کن.
- اگر متن خطا را برایم فرستادی، سریع پیدا و اصلاح می‌کنم.
